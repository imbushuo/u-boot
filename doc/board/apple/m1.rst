U-Boot for Apple Silicon Macs
=============================

Allows Apple Silicon Macs to boot U-Boot via the m1n1 bootloader
developed by the Asahi Linux project.  At this point the machines with
the following SoCs work:

 - Apple M1 SoC (t8103)
 - Apple M2 SoC (t8112)
 - Apple M1 Pro SoC (t6000)
 - Apple M1 Max SoC (t6001)
 - Apple M1 Ultra SoC (t6002)
 - Apple M2 Pro SoC (t6020)
 - Apple M2 Max SoC (t6021)
 - Apple M2 Ultra SoC (t6022)
 - Apple M3 SoC (t8122)
 - Apple M3 Pro SoC (t6030)
 - Apple M3 Max SoCs (t6031, t6034)
 - Apple M3 Ultra SoC (t6032)

On these SoCs the following hardware is supported:

 - S5L serial port
 - SPI keyboard (on M1 laptops)
 - MTP keyboard driver (requires additional device-tree nodes; see below)
 - Framebuffer
 - NVMe storage
 - USB 3.1 Type-C ports
 - ASMedia USB controller (when its firmware is available)

Device trees are provided in dts/upstream/src/arm64/apple/ for M1, M2,
and M3 (t8122) devices. The t6030/t6031/t6034/t6032 boards require
separate matching device trees; they are not yet in this upstream subtree
or in the asahi-releng branch.

Building U-Boot
---------------

.. code-block:: bash

    $ export CROSS_COMPILE=aarch64-none-elf-
    $ make apple_m1_defconfig
    $ make

This builds ``u-boot-nodtb.bin`` and all upstream Apple device trees in
``dts/upstream/src/arm64/apple/``. The trees are separate from the U-Boot
binary because m1n1 supplies the selected tree at boot. ``make dtbs`` also
builds the complete Apple set without rebuilding U-Boot. Not every Apple
device with an upstream tree is supported by this U-Boot configuration.
The video console uses the 16x32 font by default instead of 8x16.

The MTP keyboard driver matches ``apple,dockchannel-hid`` and needs
``apple,fifo-size``, an ``apple,helper-cpu`` reference to an
``apple,rtk-helper-asc4`` device, and DockChannel ``data`` and ``rmt-data``
registers. The bundled upstream Apple device trees do not yet describe
these devices, and m1n1 does not add them during handoff. As a result, the
MTP driver builds but cannot bind with those device trees. Using an older
m1n1 alone will not make the built-in MTP keyboard work.

U-Boot looks for the EFI system partition on Apple NVMe storage, preferring
the partition named by ``/chosen/asahi,efi-system-partition``. It uses this
partition for FAT-backed environment storage, EFI variables and firmware
loading. The ASMedia xHCI controller requires a separately supplied
``vendorfw/u-boot/asmedia/asm2214a-apple.bin`` on that partition; the
firmware binary is not included in the U-Boot build.

Image creation
--------------

In order to run U-Boot on an Apple Silicon Mac, U-Boot has to be used
as a payload for the m1n1 bootloader.  Instructions for building m1n1
can be found here:

    https://github.com/AsahiLinux/docs/wiki/SW%3Am1n1

.. code-block:: bash

    $ cat m1n1.macho dts/upstream/src/arm64/apple/t8103-j274.dtb \
        u-boot-nodtb.bin > u-boot.macho

This uses ``u-boot-nodtb.bin`` as the device tree is passed to U-Boot
by m1n1 after making some adjustments.

UEFI hardware handoff
---------------------

``apple_m1_defconfig`` generates ACPI tables automatically during U-Boot
startup for registered models. The root ``compatible`` list in the device
tree supplied by m1n1 selects the table set, in compatible-list order.
Unregistered models generate no ACPI tables and retain device-tree-only
handoff. On registered models, UEFI applications receive both ACPI and the
device tree. The simple framebuffer provides a UEFI graphics output protocol
with its actual pixel format and scanline stride.

Apple ACPI sources live in ``arch/arm/mach-apple/acpi/``. Each model registers
an ``APPLE_ACPI_MODEL`` with its exact compatible, compiled DSDT, table-space
budget and C table callbacks. Add a model subdirectory to its Makefile to
include a new table set. Write AML tables in ASL (``dsdt.asl``); the build uses
``iasl`` from ACPICA to compile them. Non-AML tables are ordinary C writers
using the structures in ``include/acpi/acpi_table.h``. This allows U-Boot to
fill physical addresses and checksums rather than maintaining binary files
or disassembler-generated data-table DSL.

The model's ``table_size`` reserves the complete set, including root tables,
AML and alignment. Allocations are page-aligned in the bloblist and published
as ``EFI_ACPI_RECLAIM_MEMORY``. The initial model reserves 64 KiB; the default
128 KiB relocated bloblist accommodates this plus its alignment and metadata.
Increase ``CONFIG_BLOBLIST_SIZE_RELOC`` if future model budgets require more
space. Use ``acpi list -c`` to inspect the generated tables and checksums.

The initial ``apple,j413`` set describes the MacBook Air (13-inch, M2, 2022).
It contains DSDT, FADT, MADT, GTDT, CSRT and DBG2, rooted through an XSDT.
The DSDT has a CPU container, eight CPU devices and an S5L debug UART at
``0x235200000`` (``\\_SB.UART``, placeholder HID ``APP0001``). The MADT contains
CPU-interface stubs with zero GIC addresses: it does not claim a real GIC.
The AIC2 at ``0x23b0c0000`` is instead described by a stub CSRT interrupt
controller resource. These are bring-up tables, not a complete hardware
description, and require operating-system support for Apple-specific devices.

The experimental EFI PSCI configuration table requires m1n1's CPU
spin-table handoff and an Apple watchdog. It supports starting secondary
CPUs and restarting the machine. Shutdown is advertised only when the
Apple SMC registers and SRAM are available. SMC protocol initialization
is deferred until shutdown is requested, leaving the firmware and mailbox
untouched during normal boot so that the operating system can take ownership.
CPU suspend and CPU off are not supported; there is no native SMC/HVC PSCI
firmware on this platform. The watchdog also backs UEFI ResetSystem after
ExitBootServices.

When the EFI PSCI configuration table is installed, U-Boot marks the FADT's
ARM boot flags with ``ACPI_ARM_PSCI_USE_EFI`` (reserved bit 2) and updates its
checksum. This experimental conduit must not be treated as native SMC/HVC PSCI.

With ``CONFIG_CMD_BOOTEFI_PSCITEST``, U-Boot embeds the EFI PSCI selftest.
At the U-Boot prompt, run either::

    => bootefi pscitest reset
    => bootefi pscitest poweroff

The test starts every offline secondary CPU, reports how many reached their
entry points, and waits 15 seconds before requesting the selected power
action. No disk or ``bootargs`` changes are needed. The standalone
``lib/efi_loader/pscitest.efi`` is still built for testing from an external
EFI loader. If the selected action is unavailable, the application returns
an error; once a secondary CPU has started, it keeps the image resident if
the power action returns instead of unloading code still in use.

Image installation
------------------

Instructions on how to install U-Boot on your Mac can be found at:

    https://github.com/AsahiLinux/docs/wiki/Developer-Quickstart

Just replace ``m1n1.macho`` with ``u-boot.macho`` in the instructions.

Debug UART
----------

Since the base address of the UART is SoC-dependent, the debug UART is
not enabled by default.  To enable the debug UART the base address
needs to be adjusted and the CONFIG_DEBUG_UART option needs to be
enabled.  The table below gives the correct base address for the
supported SoCs.

.. list-table::
   :widths: 32 16
   :header-rows: 1

   * - SoC
     - Base Address
   * - M1 (t8103) and M2 (t8112)
     - 0x235200000
   * - M1 Pro/Max/Ultra (t6000/t6001/t6002) and M2 Pro/Max/Ultra (t6020/t6021/t6022)
     - 0x39b200000
